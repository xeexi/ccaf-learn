2-3　ツールの粒度

数が多いと選べなくなり、1つに詰め込みすぎると引数が複雑になって間違えます。

BLUEPRINT 2.1明確な説明と境界を持つツール設計

ゴール細かすぎ・大きすぎで何が起きるか言える。

図の読み方

  1. 1左が細かすぎる例。似た道具が8個並んでいて、どれを選べばよいか判断できません。
  2. 2中央が大きすぎる例。道具は1個ですが、引数が6つあります。
  3. 3引数が増えると、正しい組み合わせは限られるのに、選べる組み合わせは膨大になります。「delete なのに dryrun を付け忘れた」のような事故が起きます。
  4. 4右がちょうどよい例。業務の1動作＝1ツールです。
大きすぎる道具が壊れる理由 do_everything(action, mode, target, format, dryrun, …)
引数が6つあれば、正しい組み合わせは限られるのに、選べる組み合わせは膨大です。「action=delete なのに dryrun を付け忘れた」のような事故が起きます。

目安は「人間の担当者が1回でやる仕事の単位」。ファイルを探す、中身を読む、書き換える ─ これくらいの粒度です。

ポイント目安は「人間の担当者が1回でやる仕事の単位」。細かすぎれば選べず、大きすぎれば引数を間違える。
