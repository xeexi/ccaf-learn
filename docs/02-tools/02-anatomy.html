2-2　ツール定義は3つの部品でできている

name（呼び名）、description（いつ使うか）、input_schema（何を渡すか）。判断に効くのは description です。

BLUEPRINT 2.1明確な説明と境界を持つツール設計

ゴール3つの部品が何を決めているか言える。

図の読み方

  1. 1中央の枠が1つの道具ぶんの定義。3段に分かれています。
  2. 2name ─ 呼び名。短く一意に。
  3. 3description ─ 右の注記のとおり、Claude が「使うかどうか」を判断する材料はここだけです。コードの中身も実際の挙動も見ていません。
  4. 4input_schema ─ 渡す引数の型・必須・選べる値。誤用を防ぐ枠です。

だから道具が呼ばれないときに直すのは、まず descriptionです。しかも「何をするか」ではなく「いつ使うか」を書きます。

書き直しの型 ✗ 何をするかだけ："コーディング規約を取得する"
○ 何をするか＋いつ呼ぶか＋いつ呼ばないか：
"コーディング規約を取得する。命名やフォーマットに触れる前に必ず呼ぶ。一般的な設計方針の質問には使わない"
誤解「description はコードのコメントのようなもの。人間が読む用」 実際はプロンプトの一部です。しかも常にコンテキストを消費しています（前提編）。丁寧に、しかし冗長にならないよう書きます。

ポイントdescription に書くべきは「何をするか」より「どんなときに使うか」。判断の条件を言語化する。
