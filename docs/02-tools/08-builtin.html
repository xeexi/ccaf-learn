2-8　組み込みのツールを選ぶ

6つの道具を、仕事で選び分ける

最初から入っている道具は6つ。同じことが複数の道具でできてしまうので、選ぶ基準が要ります。

BLUEPRINT 2.5Select and apply built-in tools (Read, Write, Edit, Bash, Grep, Glob) effectively

ゴール6つを、探し方・直し方の違いで選び分けられる。

道具何をするこれを選ぶのは
Grep中身を探す 関数名・エラーメッセージ・import 文など、文字列で探すとき
Globファイル名を探す **/*.test.tsx のように、名前や拡張子のパターンで探すとき
Read全体を読む 中身が丸ごと要るとき
Edit一部を直す 一意に当たる文字列を目印にできるとき
Write丸ごと置き換える 新規作成のとき、またはEdit の目印が一意にならないとき
Bashコマンドを実行する 上で足りないとき。ただし権限の扱いが違う（この節の下）

ポイントEdit は一意に当たる目印があってはじめて使える。当たらないときは Read で全体を読み、Write で書き戻す ── これが定石。

未知のコードベースは、全部読まない

先に読み尽くそうとすると窓が尽きます。当たりを付けてから、必要なぶんだけ読みます。

ゴール探索の順番を、道具の組み合わせで言える。

ポイント「全ファイルを先に読む」は窓を尽かす。Grep で当たりを付けて Read で追うを繰り返す。

できることが同じでも、権限の面が違う

同じ「探す」でも、専用の道具と Bash 経由では扱いが変わります。

ゴール同じ仕事でも道具によって確認が出る／出ないを説明できる。

同じ「探す」でも専用の道具（Grep / Glob）Bash で同じことをする
作業ディレクトリの中 確認を挟まずに動く 既定で確認が出る
読み取りだけの決まった命令は例外
外のパス 確認が出る 確認が出る
結果 調査を任せても止まらない 同じ調査でも毎回止まる

ポイントできることが同じでも権限の面が違う。ツール名は権限・子への配布・フックで共通の識別子。

名前が効く3か所 ・権限の設定（許可／拒否の対象）
・子に渡すツールの一覧
・フックをどのツールで発火させるかの一致条件（matcher）
まったく同じ文字列を使うので、名前を覚えることがそのまま権限設計とフック設定になります。
誤解「Bash があれば、読む・探すも全部それで済む」 実際はできることは同じでも権限の扱いが違います。「なぜ調査が毎回止まるのか」の答えがここにあることが多い。
※ 実行する場所がもう1つある ── クライアントツールとサーバツール 上の6つはあなたのアプリ（Claude Code）が実行するもので、クライアントツールと呼びます。 これとは別に、web_search や code_execution のように Anthropic 側で実行され、結果まで入って返るサーバツールがあります。 こちらは tool_result を返す往復が要りません。
サーバツールは既定10周で一区切りが付き、pause_turn が返ります ── 応答をそのまま足して投げ直せば続きます（Domain 1〈stop_reason で分岐する〉）。
