BLUEPRINT 2.5組み込みツールの選択と活用

ゴールクライアントツールとサーバツールを、実行する場所で言い分けられる。

ポイント分かれ目は「実行するコードを自分で書くか」。サーバツールは往復が要らないぶん、いちばん安く済む。

サーバツールを使うと pause_turn が返ることがある Anthropic 側の実行は既定10周で一区切りが付きます。まだ答えは出ていないので、 応答をそのまま足して投げ直します（Domain 1〈stop_reason で分岐する〉）。完了として扱うと検索の途中で終わります。

どれを選ぶか ─ 書く量が少ない順に見る

要件から使うものが決まります。上ほど自分で書く量が少なく、設問でもそちらが正解になります。

Claude Code の組み込みツール

Claude Code が最初から持っている道具は、すべてクライアントツールです。同じことが複数の道具でできてしまうので、選び分けの基準が要ります。

系統は5つ 読む Read　／　探す Grep Glob　／　変える Edit Write　／　実行する Bash　／　外に出る WebFetch WebSearch
右にいくほど、渡したときに起きうる範囲が大きくなります。「変える」の2つは、既存の一部を直すのが Edit、丸ごと置き換えるのが Write。
同じ「探す」でも専用のツール（Grep / Glob）Bash で同じことをする
作業ディレクトリの中 確認を挟まずに動く 既定で確認が出る
読み取りだけの決まった命令は例外
外のパス 確認が出る 確認が出る
結果 調査を任せても止まらない 同じ調査でも毎回止まる
名前が効く3か所 ・権限の設定（許可／拒否の対象）
・子に渡すツールの一覧
・フックをどのツールで発火させるかの一致条件（matcher）
まったく同じ文字列を使うので、名前を覚えることがそのまま権限設計とフック設定になります。
誤解「Bash があれば、読む・探すも全部それで済む」 実際はできることは同じでも権限の扱いが違います。「なぜ調査が毎回止まるのか」の答えがここにあることが多い。

ポイントできることが同じでも権限の面が違う。ツール名は権限・子への配布・フックで共通の識別子。
