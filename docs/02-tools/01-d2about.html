2-1　このドメインについて

Domain 1 は道具を使う側の組み立てでした。ここからは道具そのものの作りです。同じ仕事でも、切り方と説明文の書き方で、呼ばれるかどうかが変わります。

ゴール
  • 3つの部品が何を決めているか
  • 粒度の判断基準
  • 失敗の返し方
  • MCP が何を解決するのか
  • 誰に何を配るか、そしてそのコードを誰が動かすか

なぜ「3つの部品」から始まるのか

道具の設計を語るには、まず書ける場所がどこにあるのかを知る必要があります。書ける場所は3つしかないので、ここは短く済みます。そのあとの粒度・失敗の返し方・権限は、すべて「この3つのどこに何を書くか」の話に還ります。

誤解「ツールは実装が本体で、説明文はおまけ」 実際はモデルが見ているのは説明文だけです。実装は見えていません。呼ばれないツールの原因は、たいてい実装ではなく説明文の側にあります。

ポイントツール設計は「モデルに見えているのは説明文だけ」という一点から考えると筋が通る。
