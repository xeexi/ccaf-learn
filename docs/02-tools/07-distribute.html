2-7　誰にどのツールを配るか

全員に全部渡すのがいちばん簡単ですが、選択肢が増えるほど選び間違いが増え、事故が届く範囲も広がります。配る範囲そのものが設計です。

BLUEPRINT 2.3エージェント間へのツール配分と tool choice の設定

ゴール配る範囲を決める基準を言える。

図の読み方

  1. 1調べる子が読み取りだけなのは、権限を惜しんでいるからではありません。間違えても何も残らない状態を作るためです。調査は間違えるものだという前提の設計です。
  2. 2直す子の線引きは「取り消せるか」です。ファイル編集は戻せますが、デプロイや外部への送信は戻せません。戻せない操作だけを外すのがいちばん単純な基準になります。
  3. 3全部渡した子が危ういのは、ツールが多いこと自体でもあります。似た道具が並ぶと選び間違いが増えます（ツールの粒度）。
  4. 4子に渡すツールは、その子の定義ファイルで指定します。渡していないツールは、指示で頼まれても使えません ── ここが「お願い」ではなく決定的に効く部分です。
誤解「必要になるかもしれないので、ツールは多めに渡しておく」 実際は渡した範囲がそのまま事故の範囲です。しかも選択肢が増えるほど選び間違いも増えるので、多めに渡すことは二重に不利になります。

ポイント配る範囲＝壊せる範囲。基準は「取り消せない操作を持たせない」。

※ 渡したうえで「必ず使わせる／使わせない」を指定する方法（tool_choice）は Domain 4 の〈構造化出力と tool_choice〉にあります。ここは誰に渡すかの話です。
