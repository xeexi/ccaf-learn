3-5　スラッシュコマンドとスキル

スラッシュコマンド ─ 1ファイル＝1コマンド

ゴール手順の置き場所を4択から選べる。

毎回同じことを打ち直さずに済ませる仕組みが2つあります。よく使う手順をファイルに置くと /名前 で呼び出せ、長い作業手順は別の文脈で走らせられます。

BLUEPRINT 3.2Create and configure custom slash commands and skills

.claude/commands/deploy.md　─　先頭の --- で囲むのが YAML frontmatter

---
description: リリース前の確認1
argument-hint: <環境名>2
allowed-tools: Read, Bash3
---

$ARGUMENTS 環境のリリース前チェックを行う。4
まず $1 のテストを実行し、失敗があれば中止すること。
  1. 1description ─ 何をするコマンドか。
  2. 2argument-hint ─ 補完に出る引数の形。
  3. 3allowed-tools ─ そのコマンド実行中だけツールを絞る。権限設計としても使えます。キー名のハイフンは YAML の書き方で、JSON ではありません。
  4. 4本文に $ARGUMENTS（全部）や $1 $2（位置ごと）と書くと、呼び出し時の引数が入ります。ファイル名がそのままコマンド名です。

ポイント「毎回同じ順番でやってほしい手順」の置き場所。CLAUDE.md（常に効く）と違い、呼んだときだけ効く。

置き場所と名前空間 プロジェクト（.claude/commands/）と個人（~/.claude/commands/）の2通り。前者はチームで共有されます。
.claude/commands/db/migrate.md のように掘るとサブディレクトリが名前空間になり、数が増えても整理できます。

スキル ─ ディレクトリごと束ねる

ゴールスキルがコマンドと違う点を2つ挙げられる。

補助ファイルを伴う手順や、別コンテキストで走らせたい作業はスキルにします。

スキルは1ファイルではなくディレクトリ

.claude/skills/review/
  SKILL.md      ← 本体
  checklist.md  ← 補助
  examples/     ← 補助

ポイント補助ファイルが要る、または別コンテキストで走らせたい → スキル。単発の手順書 → スラッシュコマンド。

SKILL.md の YAML frontmatter（主なもの） description　いつ使うか ── Claude が自動で使うかどうかの判断材料。ツールの description と同じ役割
allowed-tools　実行中に使えるツール
argument-hint　引数の形
context: fork　別コンテキストで走らせる
誤解「fork すれば速くなる・賢くなる」 実際は目的はコンテキストの隔離です。引き継がれないことが利点であり、同時に渡し忘れの原因にもなります。

CLAUDE.md / コマンド / スキル の使い分け

ゴール4つの置き場所を、繰り返すものの種類で選び分けられる。

「何を繰り返したいか」で置き場所が決まります。設問はここを突いてきます。

ポイント繰り返すのが決まりごとなら CLAUDE.md、手順ならコマンド、役割ならスキル、判断の要らない処理なら hooks。

チームに影響させずに、自分用へ変える 共有のスキルを自分の好みに直すと、そのままチーム全員に効きます。
自分だけで使いたいときは ~/.claude/skills/ に別の名前で置きます（コマンドの ~/.claude/commands/ と同じ考え方）。 同じ名前のまま置くとどちらが呼ばれたのか分からなくなるので、名前を変えるのが要点です。
設問での問われ方 「毎回同じ注意を書いている」→ CLAUDE.md／「リリース手順を毎回説明している」→ スラッシュコマンド／ 「レビュー観点と参考資料をセットで使い回したい」→ スキル／「編集後に必ずリンタを走らせたい」→ hooks。

※ カスタムコマンドはスキルに統合されました。.claude/commands/deploy.md と .claude/skills/deploy/SKILL.md は、どちらも /deploy になり同じように動きます。 既存の .claude/commands/ はそのまま使えます。スキルのほうができることが多い （補助ファイルを束ねる・自動起動を止める・別コンテキストで走らせる）ので、上の切り分けはそのまま使えます。
