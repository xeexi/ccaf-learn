3-5　スラッシュコマンドとスキル

スラッシュコマンド ─ 1ファイル＝1コマンド

よく使う手順を .claude/commands/ に置くと、/名前 で呼び出せます。

BLUEPRINT 3.2カスタムのスラッシュコマンドとスキル

ゴール手順の置き場所を4択から選べる。

図の読み方

  1. 1ファイル名がコマンド名になります。deploy.md なら /deploy。
  2. 2先頭の YAML frontmatter で3つ指定できます。allowed-tools はそのコマンド実行中だけツールを絞るもので、権限設計としても使えます。
  3. 3本文の中に $ARGUMENTS や $1 と書いておくと、呼び出し時の引数が入ります。
  4. 4置き場所はプロジェクト（.claude/commands/）と個人（~/.claude/commands/）の2通り。前者はチームで共有されます。
サブディレクトリで名前空間を作れる .claude/commands/db/migrate.md のように掘ると、コマンドが整理されます。数が増えたときに効きます。

ポイント「毎回同じ順番でやってほしい手順」の置き場所。CLAUDE.md（常に効く）と違い、呼んだときだけ効く。

スキル ─ ディレクトリごと束ねる

補助ファイルを伴う手順や、別コンテキストで走らせたい作業はスキルにします。

図の読み方

  1. 1スキルはディレクトリです。SKILL.md が本体で、チェックリストや例などの補助ファイルを同梱できます。ここがコマンドとの一番の違い。
  2. 2description はClaudeが自動で使うかどうかの判断材料。ツールの description と同じ役割です。
  3. 3context: fork を付けると、別コンテキストのサブエージェントとして走ります。大量に読む作業を、親の窓を汚さずに任せられます。
  4. 4ただし fork した先は親の会話も CLAUDE.md も引き継ぎません。必要な前提は指示に書いて渡す必要があります。
誤解「fork すれば速くなる・賢くなる」 実際は目的はコンテキストの隔離です。引き継がれないことが利点であり、同時に渡し忘れの原因にもなります。

ポイント補助ファイルが要る、または別コンテキストで走らせたい → スキル。単発の手順書 → スラッシュコマンド。

CLAUDE.md / コマンド / スキル の使い分け

「何を繰り返したいか」で置き場所が決まります。設問はここを突いてきます。

判断の順序

  1. 1いつも効いていてほしいか？ → はい なら CLAUDE.md。会話のたびに載るので、短く保つ。
  2. 2呼んだときだけでよいか？ → 単発の手順ならスラッシュコマンド。
  3. 3補助ファイルが要る／別コンテキストで走らせたいか？ → スキル。
  4. 4そもそもモデルの判断が要らないか？ → それは hooks の領域です（Domain 1）。「編集したら必ず整形」のような処理は、ここに書くべきではありません。
設問での問われ方 「毎回同じ注意を書いている」→ CLAUDE.md／「リリース手順を毎回説明している」→ スラッシュコマンド／「レビュー観点と参考資料をセットで使い回したい」→ スキル／「編集後に必ずリンタを走らせたい」→ hooks。

ポイント4つの選択肢を「常に効く／呼んだとき／束ねたい／判断不要」で切り分ける。この分類がそのまま設問の選択肢になる。
