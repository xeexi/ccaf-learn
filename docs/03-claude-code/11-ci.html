3-11　非対話実行と CI/CD

人がいない場所で走らせる ─ claude -p

対話せずに1発で実行し、結果を標準出力へ、合否を終了コードで返します。

BLUEPRINT 3.6CI/CD への統合

ゴール-p が何をやめる操作なのか言える。

図の読み方

  1. 1-p（--print）を付けると非対話モード。承認ダイアログが出ないので、そのままスクリプトに乗せられます。
  2. 2結果は標準出力へ。合否は終了コードで返るので、CI のステップの成否として扱えます。
  3. 3--output-format json にすると、結果本文のほかにセッションIDや使用量が構造化されて返ります。後続処理で扱いやすくなります。
  4. 4さらに --json-schema で出力の形そのものを指定できます。Domain 4の「スキーマで受け取る」を、CLI の外側でやる形です。
つまずきやすい非対話では確認のダイアログを出せません。「危なければ人が止める」という設計が成立しないので、何を許すかを事前に決めておくのが前提になります（後述の settings.json と permissions）。

ポイント-p は「対話をやめる」だけでなく「人の承認をやめる」こと。権限設計とセットでなければ使えない。

承認できない場所では、事前に許可を決める

非対話実行では、許可の与え方が2通りあります。どちらを選ぶかが設問になります。

図の読み方

  1. 1「使うツールを列挙する」（左）── レビュー用途なら Read,Grep だけで足ります。書き込み系を渡さなければ、壊しようがありません。
  2. 2「全部許可する」（右）── 楽ですが、CI は人が見ていない場所なので、事故が起きても止まりません。設問では基本的に誤答側です。
  3. 3この2つの中間が plan（提案のみ）と acceptEdits（編集は自動、それ以外は確認）。「全部か、なしか」ではなく段階で選べるのが要点です。
  4. 4「GitHub Actions」（下）── 公式アクションを使い、APIキーはシークレットとして渡します。ワークフローのファイルに直接書いてはいけません。
設問での問われ方 「CI で自動コードレビューを走らせたい。権限はどう設定するか」
→ 読み取り系のツールだけを allowedTools で開ける。bypassPermissions は選ばない。
考え方は Domain 2 と同じです。やり直せる操作は自動、やり直せない操作は通さない。

ポイントCI は「承認する人がいない」場所。だから権限は実行前にすべて決まっていなければならない。
