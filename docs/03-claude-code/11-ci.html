3-11　非対話実行と CI/CD

人がいない場所で走らせる ─ claude -p

対話せずに1発で実行し、結果を標準出力へ、合否を終了コードで返します。

BLUEPRINT 3.6CI/CD への統合

ゴール-p が何をやめる操作なのか言える。

CI のステップに1行で乗る

claude -p "差分をレビューして" --output-format json --allowedTools "Read,Grep"

標準出力 … 結果の本文 / JSON（標準入力からパイプで渡すこともできる）
終了コード … 0 = 成功 / 0以外 = 失敗 → CI のステップの成否になる
--output-format返るもの使いどころ
text（既定）そのままの文章 ログに出すだけ
json結果本文 ＋ セッションID・使用量 後続のステップで機械的に扱う
stream-json逐次、改行区切りで流れてくる 長い処理の途中経過を見る

ポイント-p は「対話をやめる」だけでなく「人の承認をやめる」こと。権限設計とセットでなければ使えない。

さらに形を固めたいとき --json-schema で出力の形そのものを指定できます。Domain 4 の「スキーマで受け取る」を、CLI の外側でやる形です。
つまずきやすい非対話では確認のダイアログを出せません。「危なければ人が止める」という設計が成立しないので、何を許すかを事前に決めておくのが前提になります（後述の settings.json と permissions）。

承認できない場所では、事前に許可を決める

非対話実行では、許可の与え方が2通りあります。どちらを選ぶかが設問になります。

許可の与え方書き方CI での評価
使うツールを列挙する --allowedTools "Read,Grep" これが正解側　必要なものだけ開ける。書き込み系を渡さなければ壊しようがない
編集だけ自動で通す --permission-mode acceptEdits 中間。編集は自動、それ以外は確認
提案だけさせる --permission-mode plan 中間。変更させずに計画だけ出させる
全部許可する --permission-mode bypassPermissions 設問では基本的に誤答　人が見ていない場所なので、事故が起きても止まらない

ポイントCI は「承認する人がいない」場所。だから権限は実行前にすべて決まっていなければならない。「全部か、なしか」ではなく段階で選ぶ。

GitHub Actions で動かす 公式アクション anthropics/claude-code-action@v1 を使い、認証は ANTHROPIC_API_KEY または CLAUDE_CODE_OAUTH_TOKEN をシークレットとして渡します。ワークフローのファイルに直接書いてはいけません。
設問での問われ方 「CI で自動コードレビューを走らせたい。権限はどう設定するか」
→ 読み取り系のツールだけを allowedTools で開ける。bypassPermissions は選ばない。
考え方は Domain 2 と同じです。やり直せる操作は自動、やり直せない操作は通さない。
