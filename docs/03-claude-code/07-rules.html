3-7　パス固有ルール

ゴールpaths が何のスイッチか説明できる。

開発者→Claude Code

テストファイルを開いたときだけ効く規約を、どこに置くか。全部を常に読ませると窓を食うので、ファイルの種類ごとに出し分けます。

BLUEPRINT 3.3Apply path-specific rules for conditional convention loading

.claude/rules/frontend.md　─　--- で囲んだ中が YAML frontmatter

---
paths:
  - "src/**/*.{ts,tsx}"1
  - "**/*.test.ts"2
---

コンポーネントは関数コンポーネントで書く。…
  1. 1グロブを並べるだけ。{ts,tsx} のようなブレース展開が使えるので、1ファイルで複数の拡張子をまとめられます。
  2. 2複数指定できます。ファイルは .claude/rules/frontend/react.md のように掘っても自動で拾われるので、規約が増えても1ファイルが肥大しません。

ポイントpaths は「いつ読ませるか」のスイッチ。規約が増えたときに、窓を守りながら増やせる仕組み。

CLAUDE.md との使い分け 常に効かせたい規約（言語共通の方針）→ CLAUDE.md
特定の種類のファイルにだけ効かせたい規約（React コンポーネントの書き方、テストの命名）→ .claude/rules/ ＋ paths
後者を CLAUDE.md に全部書くと、関係ない作業のときも窓を食い続けます。
ディレクトリ別の CLAUDE.md で足りないとき 効かせたい相手が1つのディレクトリにまとまっているなら、そこに CLAUDE.md を置けば済みます（〈CLAUDE.md の階層〉）。
足りなくなるのは、対象がツリー中に散らばっているときです ── テストは src/ のあちこちに、 *.test.tsx という名前だけを手がかりに置かれています。ディレクトリごとに CLAUDE.md を撒くと、 同じ内容が何枚もでき、あとから増えたディレクトリには付け忘れます。
「置き場所ではなく、名前で決まる規約」は paths の glob で書きます ── paths: ["**/*.test.tsx"] の1枚で、どこにあっても効きます。 〈@import〉は分割するだけで量は減りませんが、paths は実際に載る量を減らします。
