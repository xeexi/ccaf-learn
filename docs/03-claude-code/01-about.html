3-1　このドメインについて

Claude Code を「使えるようにする」のではなく、チームの決まりごとを設定として置くのがこのドメインです。人が毎回言わなくても守られる状態をどう作るか、という話に終始します。

ゴール
  • 決まりごとをどこに置くと、いつ効くか
  • 繰り返す作業の置き場所
  • CI で先に決めておくこと
設定には2種類ある ── これがこのドメインの背骨 読ませるもの（CLAUDE.md・スラッシュコマンド・スキル・パス固有ルール）は、 窓に載ってプロンプトの一部になります。守られる確率は高いが、確率です。
通さないもの（settings.json の permissions・フック）は、実行経路そのものを塞ぎます。破りようがありません。
Domain 2 の「弱い対策と強い対策」とまったく同じ線引きで、設問はここを突いてきます。
誤解「CLAUDE.md に書けば必ず守られる」 実際はCLAUDE.md はプロンプトとして読まれるだけです。「本番には触らないで」を確実にしたいなら deny で通さないほうに書きます。どちらに書くべきかを、要件の「確実さ」から選べるようにするのがこのドメインのゴールです。

ポイント置き場所の判断は2軸だけ ── 誰に効かせたいか（範囲）と、どれだけ確実に効かせたいか（読ませる／通さない）。
