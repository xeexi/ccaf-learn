3-8　plan mode と直接実行

plan mode では、調べることはできますが変更はできません。まず計画を出させて、承認してから実行に移します。

BLUEPRINT 3.4plan mode と直接実行の使い分け

ゴールplan mode が構造的に防ぐ事故を言える。

図の読み方

  1. 1上の帯で承認が入るのは1か所だけです。方針が固まってから手が動くので、途中で方向転換が起きません。
  2. 2上の帯に「編集」がないことが本質です。下の赤帯のとおり、できないようにしてある ── 指示の書き方で守らせているのではありません。
  3. 3下の帯では承認が操作ごとに何度も入りますが、そのつど判断できるのは目の前の1操作だけです。方針の誤りに気づくのは実行後になります。
  4. 4選ぶ基準は「先に方針を確かめたいか」。決まりきった小さな変更にまで plan mode を挟むのは過剰で、設問でもそちらが誤答になります。
どちらを選ぶか plan mode 向き：影響範囲が読めない変更、未知のコードベース、後戻りが高くつく作業、方針を人と合意したい場面
直接実行 向き：やることが決まっている小さな修正、間違えてもすぐ戻せる作業
起動は --permission-mode plan、対話中は Shift+Tab でも切り替えられます。
誤解「plan mode は安全だから常に使えばよい」 実際は小さな確実な修正にまで計画の往復を挟むと、単に遅くなります。後戻りのコストが高いときの道具です。

ポイントplan mode の本質は「編集ができない」こと。だから、方針を間違えたまま手が動く事故を構造的に防げる。
