3-8　plan mode と直接実行

plan mode では、調べることはできますが変更はできません。まず計画を出させて、承認してから実行に移します。

BLUEPRINT 3.4Determine when to use plan mode vs direct execution

ゴールplan mode が構造的に防ぐ事故を言える。

どちらを選ぶか plan mode 向き：影響範囲が読めない変更、未知のコードベース、後戻りが高くつく作業、方針を人と合意したい場面
直接実行 向き：やることが決まっている小さな修正、間違えてもすぐ戻せる作業
起動は --permission-mode plan、対話中は Shift+Tab でも切り替えられます。
誤解「plan mode は安全だから常に使えばよい」 実際は小さな確実な修正にまで計画の往復を挟むと、単に遅くなります。後戻りのコストが高いときの道具です。

ポイントplan mode の本質は「編集ができない」こと。だから、方針を間違えたまま手が動く事故を構造的に防げる。

調べる量が多いときは Explore に出す

計画を立てるには先に調べる必要がありますが、その調べた過程まで本体の窓に残ると、実装に入る前に窓が尽きます。

ゴール下調べを本体でやるか、子に出すかを選び分けられる。

本体で調べるExplore に出す
窓に残るもの 読んだファイルの中身が全部残る 要約だけが返る。読んだ中身は子の窓で消える
向く場面 見るファイルが数個と分かっているとき どこにあるか分からない、何十ファイルも当たるとき
段が多いとき 2段目・3段目に入る前に窓が尽きる 段ごとに要約を持ち帰るので、最後まで持つ

ポイントplan mode は「変更させない」仕組み、Explore は「探索の残骸を持ち込ませない」仕組み。長い調査を伴う計画では、両方を使う。

plan mode と直接実行は、混ぜて使う 「どちらか一方を選ぶ」ものではありません。調べて方針を決めるところは plan mode、決まった手順を流すところは直接実行という組み合わせが基本形です。
例：ライブラリ移行 →（plan mode）影響範囲を調べて手順を合意 →（直接実行）合意した手順を流す。
