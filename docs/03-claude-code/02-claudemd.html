3-2　CLAUDE.md の階層と読み込まれ方

CLAUDE.md は4つの場所に置ける

置く場所によって「誰に効くか」が変わります。まずこの4段を覚えます。

BLUEPRINT 3.1Configure CLAUDE.md files with appropriate hierarchy, scoping, and modular organization

ゴール4つの置き場所と「誰に効くか」を対応づけられる。

ポイント組織全員＝管理ポリシー、自分だけ＝ユーザー、チーム＝プロジェクト、自分＋このリポジトリだけ＝CLAUDE.local.md。

誤解「上位の CLAUDE.md があると、下位は無視される」 実際は上書きではなく、すべて連結されます（このすぐ下）。競合したときの扱いは、書いた内容しだいです。

上書きではなく、順に足していく

ルートから作業ディレクトリへ向かって走査され、見つかったものが全部つながります。

ゴール連結されることが、窓に何をもたらすか言える。

ポイント合成であって上書きではない。だから「置けば置くほど効く」のではなく「置いた分だけ窓を食う」。

設問での問われ方 「モノレポで、パッケージごとに違う規約を適用したい」→ 各パッケージに CLAUDE.md を置く（全部をルートの1枚に詰め込まない）。
理由は2つ：関係ないパッケージの規約を読ませずに済む／ルートの1枚が肥大化しない。
いま何が読まれているかを確かめる ─ /memory 階層で合成されるので、どのファイルが効いているのか、見ただけでは分かりません。 /memory を打つと、そのセッションで実際に読み込まれている記憶ファイルの一覧が出ます。
「同じ指示なのに、あの人の手元では効かない」「先週と挙動が違う」というときは、まずこれで読まれている枚数が違わないかを見ます ── たいてい ~/.claude/ 側だけに書いてあります。
