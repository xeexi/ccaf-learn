3-2　CLAUDE.md の階層と読み込まれ方

CLAUDE.md は4つの場所に置ける

置く場所によって「誰に効くか」が変わります。まずこの4段を覚えます。

BLUEPRINT 3.1CLAUDE.md の階層・スコープ・モジュール化

ゴール4つの置き場所と「誰に効くか」を対応づけられる。

図の読み方

  1. 1管理ポリシーは組織のIT部門が置くもので、利用者側で無効化できません。企業導入の設問で出ます。
  2. 2ユーザー（~/.claude/CLAUDE.md）は自分の全プロジェクトに効きます。個人の好みはここ。
  3. 3プロジェクト（./CLAUDE.md）はチーム共有。git にコミットするのがここです。
  4. 4サブディレクトリに置くと、そのディレクトリを扱うときだけ読み込まれます。モノレポで効きます。
  5. 5CLAUDE.local.md は同じ場所に置く個人用。自動で .gitignore に入るので、共有されません。
誤解「上位の CLAUDE.md があると、下位は無視される」 実際は上書きではなく、すべて連結されます（このすぐ下）。競合したときの扱いは、書いた内容しだいです。

ポイント「誰に効かせたいか」で置き場所が決まる。組織全員＝管理ポリシー、自分だけ＝ユーザー、チーム＝プロジェクト、自分＋このリポジトリだけ＝CLAUDE.local.md。

上書きではなく、順に足していく

ルートから作業ディレクトリへ向かって走査され、見つかったものが全部つながります。

図の読み方

  1. 1走査はルート側から作業ディレクトリへ向かって行われます。
  2. 2各階層で CLAUDE.md → CLAUDE.local.md の順に読まれます。
  3. 3結果は連結。上位が下位に置き換わるのではなく、全部が並んでコンテキストに載ります。
  4. 4サブディレクトリのものだけは例外で、そのディレクトリを実際に読むときに追加されます。
設問での問われ方 「モノレポで、パッケージごとに違う規約を適用したい」→ 各パッケージに CLAUDE.md を置く（全部をルートの1枚に詰め込まない）。
理由は2つ：関係ないパッケージの規約を読ませずに済む／ルートの1枚が肥大化しない。

ポイント合成であって上書きではない。だから「置けば置くほど効く」のではなく「置いた分だけ窓を食う」。
