BLUEPRINT 3.5段階的改善のための反復手法

ゴール改善をどこへ書き戻すか答えられる。

図の読み方

  1. 1左は長い指示を1回で書くやり方。成果物が大きいので、どこがずれたのか切り分けられません。
  2. 2右は小さく頼んで、結果を見て、ずれた点を基準として書き足すループです。
  3. 3肝は最後の矢印です。気づいた基準をその場の会話で言うだけにせず、CLAUDE.md やコマンドに残す。そうすると次回から自動で効きます。
  4. 4これは第4章（プロンプト）の「例を1つ見せる」とも繋がります。ずれた出力そのものが、次の基準の材料になります。
設問での問われ方 「生成されるコードが毎回チームの規約から外れる。どうするか」
→ その場で指摘し直すのではなく、規約を CLAUDE.md に書いて次回以降に効かせる。
「大きな機能を一度に作らせたらうまくいかない」→ plan mode で方針を合意 → 小さい単位に分けて実行 → 都度確認。

ポイント改善を会話の中で終わらせない。設定ファイルに書き戻して初めて、次回から効く。
