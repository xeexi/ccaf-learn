4-8　few-shot ─ 例を見せる

説明を増やすより、例を1つ見せる

出力の形や粒度は、言葉で説明するより実物を見せたほうが速く伝わります。

BLUEPRINT 4.2出力の一貫性を高める few-shot

ゴール例をどこから選ぶべきか答えられる。

図の読み方

  1. 1「説明を厚くする」（左・赤）── 条件を言葉で積み上げるやり方。指定が増えるほど、どれかが抜けます。しかもどれが抜けたかは、出力を見るまで分かりません。
  2. 2「例を1つ見せる」（右・緑）── 入力と出力を対で1つ置くだけ。左のような条件はひとつも書いていません。
  3. 3「例が伝えるもの」（下）── その1つが同時に伝えている中身の内訳です。形式・粒度・語調。これらを言葉で全部書き出そうとすると、左の問題が起きます。
  4. 4例は入力とセットで示すのが要点です。出力だけ見せても「どんなときにその形にするのか」が伝わりません。
誤解「例は多いほどよい」 実際は例もコンテキストを消費します。効くのは最初の1〜3個で、そこから先は伸びが鈍ります。数より、下で扱う選び方です。

ポイント曖昧な依頼を長文で補うより、実物を1つ。ただし入力と出力を対で示す。

例は「難しいところ」から選ぶ

いちばん典型的な例を並べても、判断に迷う場面では効きません。

図の読み方

  1. 1「典型例ばかり」（左）── もともと迷わない場面にしか効きません。例を足したのに精度が上がらないときは、たいていこれです。
  2. 2「境界の例」（中央）── 「ここまでは該当、ここからは該当しない」という線を、例で引きます。言葉で線を引くより速く伝わります。
  3. 3「誤りの例」（右）── 理由と対で示すと、避けるべき方向が伝わります。
  4. 4「3つの決まりごと」（下）── とくに③。実際に間違えた出力を例に昇格させるのが、いちばん効率のよい増やし方です。探す手間がなく、必ず境界の例になっているからです。
Domain 3 とのつながり ③は、Domain 3 の「反復的な改善」と同じ考え方です。気づいた基準を会話で終わらせず、例として書き戻す。次回から自動で効きます。

ポイント例の価値は数ではなくどこを示すか。境界と誤りを見せると、判断が安定する。
