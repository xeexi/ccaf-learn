4-4　考えさせる ─ thinking

難しい問題は「考える場所」を与える

ゴール考えさせる場面と、そうでない場面を分けられる。

結論だけをいきなり出させると精度が落ちます。推論の過程を出力させると、そのトークン列自体が次の判断材料になります。

いきなり結論を出させる考える場所を与える
出力の並び 質問 → 結論
あいだに何もない		 質問 → 条件を並べ、順に確かめる → 結論
なぜ差が出るか 手がかりが質問だけ 途中の思考が、次の1トークンを選ぶ手がかりになる（前提編）
代償 速い・安い 思考も出力トークン。そのぶん遅く、高くなる
向く仕事 問い合わせを5種類に分類する／日付の書式を直す 規約の条件を突き合わせて可否を決める／原因を切り分ける

ポイント「難しい判断＝考えさせる」「機械的な変換＝考えさせない」。使いどころを分けるのが設計。

「thinking」は2つの意味で使われる

ゴール2種類の「考えさせる」を言い分けられる。

上の表にあった「考える場所」を、もう少し正確に分けておきます。似ていますが、片方はただのプロンプト、もう片方はAPIの機能です。

① プロンプトで考えさせる
（chain-of-thought）		② 拡張思考
（extended thinking）
やること 「順を追って考えてから答えて」と書くだけ リクエストに thinking フィールドを付ける
推論はどこに出るか ふつうのテキスト出力の中に混ざる 専用の thinking ブロックとして分かれる
API の機能か いいえ　ただのプロンプト はい
効く理屈 同じ 同じ

※ 効く理屈が同じなのは、出力が直前までの文章を手がかりに1トークンずつ選ばれるから（前提編）。途中の推論を書き出すこと自体が手がかりを増やします。①と②の違いは「どこに出るか」だけで、効き方の原理ではありません。

誤解「thinking を有効にすれば、タダで賢くなる」 実際は①も②も、思考ぶんが出力トークンとして課金されます。遅くなり、高くなります。だから使いどころを分けるのが設計です。

ポイント「考えさせる」には、プロンプトで書かせる方法とAPIの thinking を使う方法がある。効く理屈は同じで、どちらも出力トークンを食う。
