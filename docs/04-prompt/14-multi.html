4-14　多重レビュー

1回の判定を信じない構成

見落としが致命的な場面では、同じ入力を複数回・複数の観点で通します。

BLUEPRINT 4.6多重・多段レビュー構成

ゴール多重化の是非をコストで判断できる。

図の読み方

  1. 1左がmulti-instance。同じ入力を別々の観点で並行して見せ、結果を突き合わせます。
  2. 2観点を変えるのが要点です。同じ指示を3回投げても、同じ見落としをします。安全性・性能・仕様のように違う目を当てます。
  3. 3右がmulti-pass。段階で役割を変えます。1回目は広く拾い、2回目で1件ずつ潰す。
  4. 4この分業が効くのは、「広く挙げる」と「厳しく絞る」を同時にやらせると両方中途半端になるからです。Task 4.1 の基準の話と裏表です。
組み合わせる 1回目で候補を広く挙げ（再現率を優先）、2回目で1件ずつ「本当に該当するか」を検証する（適合率を優先）。
2回目は1件が1リクエストになるので、件数が多いならバッチ処理と相性が良いです（Task 4.5）。

ポイント横に並べる＝観点を変える。縦に重ねる＝役割を変える。どちらも「1回の判定を信じない」ための構成。

倍のコストを払う価値があるか

多重レビューは回数ぶん確実に高くなります。使いどころを絞る必要があります。

図の読み方

  1. 1「多重にする価値がある」（左）── 共通するのは見落としのコストが、追加の実行コストより大きいことです。この一文が判断基準になります。
  2. 2「やりすぎ」（右）── とくに「同じ指示をただ繰り返す」は効果が薄い ── 同じ見落としが3回起きるだけです。観点を変えなければ重ねる意味がありません。
  3. 3「安く重ねる工夫」（下）── 2回目以降の対象を絞るのが最も効きます。全件を2回通す必要はありません。
  4. 4急がない検証パスはバッチに回せば半額です。多重レビューとバッチは組み合わせやすい。
誤解「多重にすれば精度が上がる」 実際は上がるのは観点や役割を変えたときだけ。同じ指示の繰り返しは、コストだけが倍になります。

ポイント多重化の判断は「精度が上がるか」ではなく「見落としのコストが実行コストを上回るか」。
