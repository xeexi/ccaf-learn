4-2　system / user / assistant

3つの役割は、効く範囲が違う

メッセージには役割があり、効き方が違います。system は会話の全期間にわたって効きます。

ゴール恒久のルールと可変の入力を、書く場所で選び分けられる。

ポイント役割の使い分けを誤ると、指示が薄まる。恒久ルールは system、可変の入力は user。

誤解「system は1回送れば、あとは覚えている」 実際は毎回のリクエストに、そのまま入って送られています（前提編）。「ずっと効く」のは、毎回送っているからです。
同じ内容でも、置き場所で結果が変わる ✗ 毎ターンの末尾に「返金額は約束しないでください」→ 書き忘れた回に破られる。毎回トークンも食う
○ system に1回だけ書く → 全ターンに効く。会話が長くなっても消えない

system の値は変えられるのか

変えられます。毎回のリクエストに入れる欄なので、途中で別の内容を送っても動きます。ただし実務では固定して使います。

ゴールsystem を途中で書き換えない理由を2つ言える。

途中で書き換えると何が起きるか
キャッシュが全部無効になる キャッシュは「ツール定義 → system → 会話」の順に積まれている。system を書き換えると、その後ろの会話ぶんもまとめて作り直し（前提編）
前提が食い違う 前半の応答と後半の応答が、別の前提で書かれた状態になる。あとから読み返しても、なぜその答えになったのか追えない

ポイント日付やユーザー名のように毎回変わる情報は user 側（末尾）へ。役割そのものを切り替えたいなら、書き換えるより別のセッションやサブエージェントに分ける（Domain 1）。

誤解「system に書けば絶対に守られる」 実際は強く効きますが、あくまで確率的です。絶対に守らせたいことは、権限設定やコードで塞ぎます（Domain 2・Domain 5）。
