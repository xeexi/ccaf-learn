1-14　子はどう起こすのか

ゴール子に載るものと載らないものを言い分けられる。

親が子のエージェントを起こす操作は、道具を1回呼ぶだけです。難しいのは起こし方ではなく、子の最初の状態に何が載るかのほうにあります。

BLUEPRINT 1.3Configure subagent invocation, context passing, and spawning

ポイント起動は簡単。難しいのは「子の最初の状態に何を載せるか」を親が決めきること。

実物を見る ─ 子の定義ファイル

ゴール定義ファイルの3つの欄が、それぞれ何を決めるか言える。

「どの型の子か」はファイルで決めます。SDK でいう AgentDefinition にあたるもので、置くだけで使えます。

.claude/agents/log-reader.md ─ YAML frontmatter ＋ 本文

---
name: log-reader1
description: ログから該当箇所だけを抜き出す。原因の切り分けを頼まれたときに使う2
tools: Read, Grep, Glob3
---

渡された条件に合う行だけを探し、次の形で返すこと。4
・見つかった行（ファイル名と行番号つき）
・見つからなかった条件
本文は貼らず、件数と場所だけを返す。
  1. 1呼び名。ファイル名ではなくこの値で識別されます（小文字とハイフン）。
  2. 2親がどの子に任せるかを決める材料。「いつ呼ぶか」を書きます ── 用途が書かれていないと呼ばれないのは、ツールの description と同じ理屈です。
  3. 3使わせる道具。書かなければ全部を引き継ぎます。ここが配る範囲そのもの（Domain 2 の〈誰にどのツールを配るか〉）。
  4. 4--- の下の本文が、そのまま子のシステム指示になります。子はこれと作業ディレクトリくらいしか持たずに立ち上がるので、返してほしい形はここに書ききります。

ポイント定義ファイルは description（いつ呼ぶか）・tools（何を使わせるか）・本文（何をどう返すか）の3つ。SDK の AgentDefinition と同じ中身で、Claude Code では置くだけで使える。

※ ~/.claude/agents/ に置くと、どのプロジェクトでも使えます。同じ name があるときはプロジェクト側が優先されます（コマンドやスキルと同じ考え方）。

3体まとめて起こす ─ 並列ツール使用

ゴール並列に起こしたとき、往復が何回になるか答えられる。

同時に走らせるための特別な仕組みはありません。1つの応答に tool_use を複数入れるだけです。

ポイント並列とは「1つの応答に複数の tool_use が入ること」。速くなるのは待ち時間だけで、往復の回数が減るぶん少し安くなる。

渡すときは、中身と出どころを分ける 調べた結果を文章にまとめて渡すと、どこから来た情報かが本文に溶けます。次の子がそれを要約した時点で、もう復元できません。 { "text": "…", "source": "…/spec.md", "page": 12 } のように本文と出どころを別の欄にして渡せば、何段先まで運んでも対応が崩れません。 文書名・ページ番号・URL は本文に混ぜず、欄で持つ（Domain 5 の〈壊れたことに気づける〉と同じ話）。
分けてよいのは、互いに結果を要らない仕事だけ 「A を調べてから、その結果で B を調べる」は並列にできません。先に結果が要る仕事は、別の往復になります。 独立しているかどうかを決めるのは親です。
誤解「子を並列に立てれば、そのぶん速く安く終わる」 実際は短くなるのは待ち時間だけで、トークンの総量は減りません。同時に走らせる数にも上限があり、超えた起動は失敗します。

※ 子を起こすツールの名前は、公式ドキュメントでは Agent。出題ガイドや古い資料では Task と表記される場合があります（TaskCreate などの Task… 系はタスク一覧の操作で、別物）。親にそのツールを渡していないと子を起こせません ── 出題ガイドは allowedTools に Task を含めること、という書き方をしています。
※ 同じ地点から複数の枝を試したいときは、子を起こすのではなくセッションを分岐させます（fork_session／CLI は --fork-session。〈セッションをまたぐ〉）。
