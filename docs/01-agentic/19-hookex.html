1-19　実物を見る ─ commit をテストで止める

ゴールフックに何が届き、何を返すと止まるかを言える。

Claude→フック→ツール

ここまでは登録の仕方でした。走らせるプログラムの中身も見ておきます。「コミットの前にテストを通して」と頼む代わりに、通らなければ commit そのものを実行させない形にします。

TASK STATEMENT 1.5Apply Agent SDK hooks for tool call interception and data normalization

settings.json ─ どのツールに効かせるか

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",1
        "hooks": [
          { "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/pretest.sh" }
        ]
      }
    ]
  }
}

.claude/hooks/pretest.sh ─ 走らせるプログラム

#!/bin/bash
cmd=$(jq -r '.tool_input.command')2

case "$cmd" in
  *"git commit"*) ;;3
  *) exit 0 ;;
esac

if npm test --silent; then
  exit 04
fi
echo "テストが落ちています。直してから commit してください。" >&2
exit 25
  1. 1matcher が見るのはツール名です。git commit も npm test も、Claude Code では Bash ツール越しに走ります。だからここは Bash。
  2. 2フックには、そのとき実行されようとしている引数が標準入力に JSON で届きます。Bash なら tool_input.command に文字列が入っています（tool_name や cwd も一緒に来ます）。
  3. 3上の指定はすべての Bash に掛かるので、絞るのはここ。ls のたびにテストが走っては使えません。
  4. 4exit 0 は「許可」ではなく「意見なし」。ここから先は、いつもどおりの権限の流れに戻ります。
  5. 5止めるのは exit 2。標準エラーに書いた文がそのままモデルに届きます。「どうすれば通るか」まで書けば、Claude はテストを直してから commit をやり直せます。

ポイント頼むのをやめて、通れない道にする。フックが見るのは tool_input、返すのは終了コード ── 覚えるのはこの2つ。

誤解「matcher に "git commit" と書けばよい」 実際はmatcher が見るのはツール名だけです。コマンドの中身で絞るのは、上のようにフックの中で行います。

※ if を書いて、フックを呼ぶ前に絞ることもできます（"if": "Bash(git commit*)"）。ここで中で見ているのは、フックに何が届くかを先に掴んでおくためです。
