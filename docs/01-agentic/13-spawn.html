1-13　子はどう起こすのか

起動そのものはツールを1回呼ぶだけです。設計の勘所は、起動の仕方ではなく子の最初の状態に何が載るかにあります。

BLUEPRINT 1.3サブエージェントの起動・文脈の受け渡し

ゴール子に載るものと載らないものを言い分けられる。

図の読み方

  1. 1親が渡すのは2つだけです。型を指定しなければ汎用の子が立ちます。凝った受け渡しの仕組みは要りません。
  2. 2定義ファイルの description は自分用のメモではありません。親がどの子に任せるかを決める材料がこれなので、用途が書かれていないと呼ばれません。ファイル名は name と一致していなくてよい。
  3. 3載らないもの（赤）が実務でいちばん事故ります。渡し忘れた前提は、子がそれを知らないまま作業して、もっともらしい誤答として返ってきます。
  4. 4載るもの（緑）に CLAUDE.md が入っているので、プロジェクト共通の決まりは書き直さなくても届きます。逆に「この調査では vendor/ を見ない」のようなその場かぎりの条件は指示に書く必要があります。
誤解「子を並列に立てれば、そのぶん速く安く終わる」 実際は短くなるのは待ち時間だけで、トークンの総量は減りません。同時に走らせる数にも上限があり、超えた起動は失敗します。

ポイント起動は簡単。難しいのは「子の最初の状態に何を載せるか」を親が決めきること。

※ 子を起こすツールの名前は、公式ドキュメントでは Agent。出題ガイドや古い資料では Task と表記される場合があります（TaskCreate などの Task… 系はタスク一覧の操作で、別物）。
