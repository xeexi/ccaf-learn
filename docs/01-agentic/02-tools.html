1-2　ツールを渡すとは、説明書を渡すこと

ツールを使えるようにする＝関数を渡すのではなく、「こういう道具があります」という説明をプロンプトに同梱することです。

BLUEPRINT 2.1Design effective tool interfaces with clear descriptions and boundaries

※ 出題は Domain 2 のタスクですが、ループを読む前にツールの渡り方を知っておく必要があるので、ここで扱います。設計そのものは Domain 2 で改めて扱います。

ゴール呼ばれないツールの原因を description から疑える。

ポイントdescription は「人間向けのメモ」ではなく、Claudeが使う／使わないを判断する唯一の材料。ここが曖昧だと道具は正しく選ばれない。

呼ばれない道具を呼ばれるようにする

同じ道具、説明文だけを変えた場合 ✗ description: "ファイルを検索する"
→ 何をするかは分かるが、いま呼ぶべきかが分からない。雑談の途中で呼んでよいのか判断できない。

○ description: "ファイルの中身を文字列で検索する。どこにあるかを答える前に必ず呼ぶこと"
→ 呼ぶ条件が書いてあるので、迷わない。
誤解「ツールを渡した＝Claude がそれを実行できるようになった」 実際は「実行してほしい、と言えるようになった」だけ。実行するのは今も昔もアプリ側です。
