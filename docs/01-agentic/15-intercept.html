1-15　ツール呼び出しに割り込む

フックはツールの前後に割り込みます。できるのは4つ ── 止める・入力を書き換える・出力を差し替える・記録する。前節の関門は、このうち「止める」だけを使った形です。

BLUEPRINT 1.5hooks によるツール呼び出しの介入とデータ正規化

ゴール割り込みでできる4つを言い分けられる。

図の読み方

  1. 1割り込める場所は2つだけです ── ツールが動く前と後。前で引数、後で返り値に手を入れます。
  2. 2② 入力を書き換えるが効くのは、モデルに正しい引数を出させるより確実で安いからです。「必ずこのディレクトリの下に書いて」と頼む代わりに、パスを書き換えます。
  3. 3③ 出力を差し替えるは前提編とつながります。モデルが読む前に整えるので、整えた後の形しか窓に載りません。生の巨大な返り値を履歴に残さずに済みます。
  4. 4④ 記録するは待たずに進む形も選べます。記録のために毎回止まる必要がないので、通知やログ送信を挟んでも遅くなりません。
  5. 5下の一文が要点です。フックは「禁止するもの」ではなくデータを通す前後で整える場所。この見方だと、①はその一機能にすぎません。

実物を見る ─ 入力の書き換え

PreToolUse が返す JSON

{
  "hookSpecificOutput": {1
    "hookEventName": "PreToolUse",
    "updatedInput": { "file_path": "/sandbox/notes.md" },2
    "permissionDecision": "allow"3
  }
}
  1. 1updatedInput は必ず hookSpecificOutput の中に置きます。外側に書くと効きません ── 公式ドキュメントが躓きどころとして挙げている点です。
  2. 2元の引数を書き換えるのではなく新しい値を返します。ここではモデルが出したパスを、サンドボックス配下に差し替えています。
  3. 3書き換えた入力をそのまま通すなら allow、人に見せるなら ask。指定を省いても書き換えは効き、通常の権限判定に流れます。
判定が競合したときの優先順位 deny ＞ defer ＞ ask ＞ allow
どれか1つが deny を返せば、他が何を返しても実行されません。禁止が最も強いと覚えます。
※ defer（あとで判断する）と入力の書き換えは併用できません。書き換えが捨てられます。
誤解「フックは危険な操作を止めるための仕組み」 実際は止めるのは4つのうち1つです。入力と出力を整える用途 ── パスの差し替え、資格情報の注入、返り値の形を揃える ── も同じ場所で行います。設問では「止める」以外を問われることがあります。

ポイント割り込める場所は前と後の2つ。できることは止める・入力を書き換える・出力を差し替える・記録するの4つ。

※ 「必ず起きてほしい処理を仕組み側に置く」という考え方そのものは Domain 5 の〈確実にしたいことは仕組み側へ〉にあります。ここはその割り込み口の中身です。
