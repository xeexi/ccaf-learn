1-15　ツール呼び出しに割り込む

フックはツールの前後に割り込みます。前節の関門は、このうち「止める」だけを使った形です。

BLUEPRINT 1.5Apply Agent SDK hooks for tool call interception and data normalization

ゴール割り込みでできる4つを言い分けられる。

ポイント割り込める場所は前と後の2つ。できることは止める・入力を書き換える・出力を差し替える・記録するの4つ。

誰が、何をしているのか

フックは「Claude が動かすもの」ではありません。呼ぶのも、返ってきた判定を適用するのも Claude Code（アプリ）です。モデルは最初に「使いたい」と言っただけで、以降には関われません。

どこに、どう登録するか ─ matcher

フックは settings.json に3階層で書きます。どのツール呼び出しに効かせるかを決めるのが matcher です。

ゴールmatcher の書き方で、効く範囲を絞れる。

settings.json ─ Write と Edit のときだけ走らせる

{
  "hooks": {
    "PreToolUse": [                       // ① いつ ─ イベント
      {
        "matcher": "Write|Edit",          // ② どのツールに ─ 省略すると全部
        "hooks": [
          { "type": "command",              // ③ 何を走らせるか
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/check.sh" }
        ]
      }
    ]
  }
}
matcher の書き方効く範囲解釈
省略 / "" / "*" 全ツール 絞り込みなし。書き忘れるとここになる
"Write" そのツールだけ ふつうの文字列として一致を見る
"Write|Edit" 列挙したツール | か , で並べる
"mcp__github__.*" MCP サーバ単位でまとめて 英数字・_・-・空白・,・| 以外の文字が入ると正規表現として読まれる

ポイントmatcher は「どのツール呼び出しに効かせるか」を決める唯一の場所。書かなければ全ツールに掛かるので、重い検査を全部に走らせてしまう事故が起きる。

※ MCP のツールは mcp__<サーバ名>__<ツール名> という名前になるので（Domain 2）、mcp__github__.* のようにサーバ単位でまとめて掛けられます。
※ matcher が何を絞るかはイベントによって違います。PreToolUse / PostToolUse はツール名ですが、SessionStart では「どうやって開始したか」（startup / resume / clear / compact）を絞ります。UserPromptSubmit や Stop のように matcher を持たないイベントもあります。

いつ走らせるか ─ 主なイベントと、止め方

割り込める場所はツールの前後だけではありません。どこで止められるかは、イベントごとに決まっています。

ゴール主なイベントと、フックが処理を止める仕組みを言える。

イベントいつ走るか止められるか
PreToolUseツールを実行する直前 止まる　実行させない
PostToolUseツールが成功した直後 止まらない　整形と記録の場所
UserPromptSubmit利用者の入力が Claude に渡る前 止まる　送らせない
SessionStart / SessionEndセッションの開始・再開／終了 止まらない　前提の注入や後片付けに使う
Stop / SubagentStop応答が終わったとき／子が終わったとき 止まる　「まだ終わらせない」ができる
PreCompact履歴の圧縮が走る前 止まる　消えては困るものを退避できる
NotificationClaude Code が通知を出すとき 止まらない　外部への通知に使う

※ ほかにも権限判定・ファイル変更・ワークツリーなどのイベントがあります。設問で問われるのは、上のツールの前後とセッションの前後です。

止めるかどうかは、フックの終了コードで決まる 0　… 正常。標準出力の JSON（上の hookSpecificOutput）が読まれる
exit 2　… ブロック。標準出力の JSON は無視され、標準エラーの文字がモデルに返る
それ以外　… 非ブロックの失敗。処理はそのまま進み、記録に残るだけ
誤解「異常終了させれば止まる。exit 1 でよい」 実際は1 では止まりません。「エラーは出たが処理は続行」の扱いになります。止めたいなら exit 2 と、モデルに読ませたい理由を標準エラーへ。しかも PostToolUse のようにそもそも止まらないイベントでは、exit 2 でも実行済みの操作は戻りません。

ポイント止めるのは exit 2（1 ではない）。取り消せない操作は「後」ではなく「前」で止める ── PostToolUse で気づいても手遅れ。

実物を見る ─ 入力の書き換え

PreToolUse が返す JSON

{
  "hookSpecificOutput": {1
    "hookEventName": "PreToolUse",
    "updatedInput": { "file_path": "/sandbox/notes.md" },2
    "permissionDecision": "allow"3
  }
}
  1. 1updatedInput は必ず hookSpecificOutput の中に置きます。外側に書くと効きません ── 公式ドキュメントが躓きどころとして挙げている点です。
  2. 2元の引数を書き換えるのではなく新しい値を返します。ここではモデルが出したパスを、サンドボックス配下に差し替えています。
  3. 3書き換えた入力をそのまま通すなら allow、人に見せるなら ask。指定を省いても書き換えは効き、通常の権限判定に流れます。
判定が競合したときの優先順位 deny ＞ defer ＞ ask ＞ allow
どれか1つが deny を返せば、他が何を返しても実行されません。禁止が最も強いと覚えます。
※ defer（あとで判断する）と入力の書き換えは併用できません。書き換えが捨てられます。
誤解「フックは危険な操作を止めるための仕組み」 実際は止めるのは4つのうち1つです。入力と出力を整える用途 ── パスの差し替え、資格情報の注入、返り値の形を揃える ── も同じ場所で行います。

※ 「必ず起きてほしい処理を仕組み側に置く」という考え方そのものは Domain 5 の〈確実にしたいことは仕組み側へ〉にあります。ここはその割り込み口の中身です。
