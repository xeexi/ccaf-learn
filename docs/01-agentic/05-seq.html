1-5　誰が、何を送っているのか

「どちらからどちらへ、何が渡ったか」を時間順に並べます。向きさえ固定して覚えれば、あとの章はすべてこの上に乗ります。

BLUEPRINT 1.1エージェントループの設計と実装

ゴール送る側と返る側で、何が渡るのかを言える。

この2つは扱いが違う。tool_use は content の中身なので次の往復で履歴として送り返すが、stop_reason は content の外側のメタデータで履歴に入らない ── つまり窓を食わない。usage や id も同じ。

ポイント送るのは messages、返るのは content と stop_reason。この向きさえ固定して覚えれば、あとの章はすべてこの上に乗る。

向きを取り違えないために

2 と 4 のあいだ、モデルは動いていません。待っているのではなく、2 で処理が終わっているだけです。次に動くのは、アプリが 4 を送った瞬間です。

誤解「アプリが tool_use を送り、以降は stop_reason を送り続ける」 実際は向きが逆です。アプリが送るのは常に messages（その中に tool_result を入れる）。tool_use と stop_reason は、毎回モデルから返ってくる側です。stop_reason は「以降ずっと」ではなく、1回目の応答にも付いています。
3往復すると、どうなるか アプリ → Claude が3本になり、そのたびに messages が長くなります。
返りも3本で、最後の1本だけが end_turn、それまでは tool_use です。
ループが回るとは、この往復が増えることにほかなりません。
