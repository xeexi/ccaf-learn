作業は1回で終わりません。前回の続きから始めるか、途中から枝を作るか、まっさらから始めるかを選びます。

BLUEPRINT 1.7Manage session state, resumption, and forking

ゴール再開・枝分かれ・新規の使い分けができる。

再開枝分かれ新規
コマンド claude --continue（直前）
claude --resume（一覧から選ぶ）		 claude --resume <id> --fork-session claude
もとの会話 そのまま伸びる 変わらない。別 ID で枝ができる 関係しない
選ぶ場面 続きをやる 同じ地点から複数の案を試して比べる 前の文脈が邪魔なとき
窓の重さ 軽くならない。長くなった会話は長いまま戻る 軽くならない。枝を切った地点の重さを引き継ぐ 軽い。ただし前提の渡し直しが要る

ポイント再開は文脈を保つ手、枝は同じ地点から分ける手、新規は文脈を捨てる手。窓を軽くするのはどれでもない。

新規を選ぶと渡し直しの手間が増えるので、CLAUDE.md に書けることは先に書いておくと楽になります。

再開したら、その間に変わったものを必ず伝える 履歴には調べた当時のファイルの中身が残っています。そのあとコードを直していると、 モデルは古い中身のまま考え続けます ── しかも食い違いに気づく手段がありません。
再開したら「src/api.ts と src/db.ts を直した」と変えた場所だけ伝えます。 全部を調べ直させるより速く、古い前提も消えます。
古い結果を抱えたまま再開するより、新規＋要約のほうが確実 前の文脈がおおむね生きているなら再開が速い。ですがツールの結果が軒並み古いなら、 再開は「間違った前提を全部持ち込む」ことになります。そのときは新規で始めて、確定した結論だけを要約して渡すほうが確実です。
判断の基準は「履歴のうち、いま読み返しても正しいものが多いかどうか」です。
誤解「セッションを再開すれば、軽い状態から始まる」 実際は履歴ごと復元されるので、再開した時点の重さがそのまま戻ります。軽くしたいなら圧縮するか、新規で始めて必要な前提だけ渡します。
