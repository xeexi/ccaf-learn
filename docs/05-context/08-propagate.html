5-8　失敗を親まで届ける

子の失敗は要約に紛れて消えます。何体か走らせたときに「全部うまくいった」ように見えるのが最も危険です。

BLUEPRINT 5.3複数エージェント間のエラー伝播

ゴール部分的な失敗を落とさない返し方を設計できる。

図の読み方

  1. 1左の3体のうち1体だけが失敗しています。この形がいちばん見つけにくい失敗です ── 全滅なら誰でも気づきます。
  2. 2上（赤）が危ういのは、嘘をついていないところです。書かれていることは正しく、書かれていないことがあるだけ。だから読んでも違和感が出ません。
  3. 3下（緑）の2つ目の欄が要点です。できなかったことを書く場所を先に作ると、空欄かどうかで機械的に判定できます（引き継ぎ票と同じ考え方）。
  4. 4いちばん下の一文が役割分担です。打ち切るかどうかを子に決めさせない ── 子は自分の範囲しか見えていないので、全体の判断ができません。
誤解「子が失敗したら、例外や異常終了で親に伝わる」 実際は子は自分の中で失敗を処理して、要約だけを返します。返す形に欄を作っていなければ、失敗は要約から抜け落ちたまま親に届きます。

ポイント部分的な失敗がいちばん危ない。返す形に「できなかったこと」の欄を作り、続行の判断は親が持つ。
