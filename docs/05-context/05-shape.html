5-5　返す量を設計する

窓を守るいちばん確実な手は、載せてから減らすことではなく、載せる前に減らすことです。減らす場所はツールの返り値です。

BLUEPRINT 5.4大規模コードベース探索での文脈管理

ゴールツールの返し方で窓の消費が決まることを説明できる。

図の読み方

  1. 1生の結果の段階では、まだ履歴に入っていません。ここが唯一「捨てても無料」な地点です。
  2. 2赤い そのまま返すが効くのは1周だけではありません。以降のすべての周回で送り直されます（前提編）。1回の油断が最後まで残ります。
  3. 33つの手のうち置き場所だけ返すがいちばん軽い。読むかどうかをモデルに選ばせられるので、要らなければ0行で済みます。
  4. 4絞る条件はツールの引数として持たせます。「短く返して」と頼む形にすると、守られるかどうかが確率になります（前節）。
誤解「窓が大きいモデルを使えば、返す量は気にしなくてよい」 実際は窓は入力と出力で食い合う共有資源です。埋まるほど1周あたりの費用と待ち時間も増えます。大きい窓は余裕であって、無料ではありません。

ポイント減らす場所は「履歴に入る前」。返す量はツールの設計で決める。
