結論の出典
どの資料の、どこから		 結論が正しいかを人が確かめられない。あとで裏取りするための唯一の手がかりが消える

ポイント結論だけを残すと直せない ── もっともらしく見えるので、間違いに気づく契機そのものがなくなる。呼んだ内容と出典（information provenance）を残し、やり直しても壊れない形にしておく。

出典には「いつのものか」も持たせる 同じ項目に違う数字が並んだとき、矛盾なのか、時点が違うだけなのかは日付がないと分かりません。 「35%」と「41%」は、2024年と2026年の調査ならどちらも正しいのに、日付を落とすと食い違いに見えます。
出典の欄には文書名・場所とあわせて、公表日か取得日を入れます。
食い違ったら、選ばずに両方残す 信頼できる出どころ同士で数字が割れることがあります。ここで片方を選ばせてはいけません ── どちらを捨てたかが記録に残らないからです。
両方を、それぞれの出典つきで残し、割れている事実に注記を付けます。どちらを採るかは、全体を見ている側（親や人）が決めます。
出し方も中身に合わせます ── 数字は表、経緯は文章、確認事項は箇条書き。全部を同じ形に均すと、読み取れるものが減ります。
記録は仕組み側に置ける 記録は判断が要らない処理です。だから〈確実にしたいことは仕組み側へ〉の線引きに従って、モデルに頼まずフックなど仕組み側に置けます。
やり直しを安全にする 同じ操作を2回走らせても結果が変わらない形（同じ ID で登録し直すと上書きになる、など）にしておくと、途中で失敗しても記録を見て途中から再実行できます。
逆に「呼ぶたびに1件増える」形だと、再実行が二重登録になり、記録があっても直せません。
