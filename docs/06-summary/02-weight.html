6-2　本番はシナリオで出る

ゴール避けにくいドメインを、シナリオの本数で言える。

60問はドメイン別に並んでいるのではなく、状況（シナリオ）ごとにまとまって出ます。しかも用意された6本のうち4本しか出ません。時間の使い方は、配点よりこちらで決まります。

本番のシナリオ（6本のうち4本が出る）主に問うドメイン
① 問い合わせ対応エージェント
返品・請求・アカウントの曖昧な依頼を扱う。自社システムへは MCP の道具4本（get_customer / lookup_order / process_refund / escalate_to_human）で繋ぐ。初回解決 80% 以上を狙いつつ、いつ人に渡すかを見極める		1・2・5
② Claude Code でコードを書く
生成・リファクタリング・デバッグ・文書化に使う。カスタムのスラッシュコマンドと CLAUDE.md で開発の流れに組み込み、plan mode と直接実行の使い分けを判断する		3・5
③ 複数エージェントの調査システム
コーディネータが専門の子に委任する ── Web 検索・文書分析・統合・報告書生成。出典つきの網羅的な報告を作る		1・2・5
④ 開発者向けの道具づくり
未知のコードベースの探索、レガシーの理解、定型コードの生成、繰り返し作業の自動化。組み込みツール（Read, Write, Bash, Grep, Glob）と MCP サーバを使う		1・2・3
⑤ CI に組み込む
CI/CD の中で自動レビュー・テスト生成・PR へのフィードバックを回す。実行できる指摘を出し、誤検知を減らすプロンプトを設計する		3・4
⑥ 書類から構造化して抜き出す
非定型の文書から情報を抜き、JSON スキーマで検証して高い精度を保つ。例外をうまく扱い、下流の仕組みに繋ぐ		4・5

ポイントDomain 5 はどのシナリオを引いても出てくるので、薄くても穴を作らない。Domain 4 は2本に集中しているので、引いたときにまとめて落とさないよう深さが要る。

配点の帯はトップページにあります ドメインごとの問題数（27% / 18% / 20% / 20% / 15%）はトップの「何が、何問出るか」にあります。 ここに同じ図を置いていた時期がありますが、同じ数字を2か所に置くと片方が古くなるので、出所はトップだけにしています。
残り時間が少ないときの順番 ① Domain 5（どれを引いても出る）→ ② Domain 1・2・3（3本ずつ）→ ③ Domain 4（2本だが、引くと濃い）
合格点は1,000点満点で720点。満点を狙う試験ではないので、広く出るところから埋めるほうが効きます。
