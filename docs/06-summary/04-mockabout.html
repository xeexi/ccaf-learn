6-4　シナリオで解く

ゴール状況から、過剰でない手を選べる。

実際の設問は、単独の用語ではなく状況を読んで一番適切な手を選ぶ形で出ます。ここまでの内容を、ドメインをまたいだ7つの状況で試します。

その7つが、このあとの7項です。各項に状況と設問がまとまっているので、状況を見ながら答えられます。

この教材の7つ（＝このあとの7項）主に問うドメイン本番のどれに当たるか
① 社内の問い合わせに答えるエージェント 1・2・5問い合わせ対応
② 未知のコードベースの不具合調査 1・5複数エージェントの調査 ／ 開発者向けの道具
③ 5人のチームに導入する 3Claude Code でコードを書く
④ 請求書から項目を抜き出す 4・5書類から構造化して抜き出す
⑤ 社外サービスを繋ぐ 2対応なし ─ MCP の追加演習
⑥ 300ファイルの一括移行 1・4対応なし ─ 分解と検証の追加演習
⑦ CI に自動レビューを組み込む 3・4CI に組み込む

※ 表の①〜⑦は、各項の見出しに付いている番号です（目次でもこの順に並んでいます）。
※ 本番のシナリオ6本と、どのドメインが何本に出るかは〈本番はシナリオで出る〉にあります。⑤⑥は本番に対応するシナリオがありませんが、Domain 2 と分解・検証を通すのに使えるので残しています。

選び方の基準

迷ったら「効く一番単純な手」を選びます。誤りの選択肢の作られ方には型があり、公式の例題の解説から洗い出したものが〈誤りの選択肢には型がある〉にあります。先に型で外してから、残りを比べると速く済みます。

本番との違い ─ 2つ ・本番は6つのシナリオのうち4つが出ます。どれが出るかは選べないので、ここの7つは全部やっておきます
・本番には複数選ぶ設問が混じります（何個選ぶかは設問に書かれています）。この教材の設問はすべて1つ選ぶ形なので、 「当てはまるものをすべて選べ」と言われたときに、2つ目・3つ目を探す癖だけは別に付けておいてください

ポイント問われているのは知識の量ではなく、対処の大きさが状況に合っているかどうか。
