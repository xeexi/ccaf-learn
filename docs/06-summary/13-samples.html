6-13　誤りの選択肢には型がある

ゴール選択肢を読んだとき、誤答の型を先に見分けて外せる。

公式 Exam Guide の「9. Sample Questions」には、解説つきの例題が並んでいます ── なぜその選択肢が正解で、他がなぜ誤りかまで書かれた、いちばん確かな材料です。設問そのものはここに載せません。ここに置くのは、その誤答をすべて分類した結果です。

誤答の型（36個ぶんを分類）こう見えるなぜ誤りか
① 事実で消える
36個中 8個		 存在しない機能・置き場所の誤り・仕様の誤解 知っていれば読んだ瞬間に消える。考える前に、まずこれを外す
公式の解説より ─ “describes a configuration mechanism that doesn't exist”
② 手が大きすぎる
36個中 7個		 分類器・学習・ルーティング層・上位モデル・道具の統合 まだ試していない小さい手が残っている
公式の解説より ─ “over-engineered, requiring labeled data and ML infrastructure when prompt optimization hasn't been tried”
③ 頼んで守らせる
36個中 5個		 system に「必ず〜」と書く／例を足す／推論に任せる 外せない条件は、頼むのではなく機械で止める
公式の解説より ─ “rely on probabilistic LLM compliance, which is insufficient when errors have financial consequences”
④ 運任せに賭ける
36個中 7個		 「進めれば見えてくる」「たいてい速い」「あとで切り替える」 保証のないものを、保証が要るところに使っている
公式の解説より ─ “ignores that the complexity is already stated in the requirements”
⑤ 原因が遠い
36個中 5個		 受け取った側を直す／症状の出た場所を直す／別の問題を解く 壊れているのは渡す前。下流は指示どおり動いている
公式の解説より ─ “incorrectly blame downstream agents that are working correctly within their assigned scope”
⑥ 逃がす
36個中 4個		 握りつぶす／全体を止める／人の運用でしのぐ その場は収まるが、仕組みは何も良くなっていない
公式の解説より ─ “shifts burden to developers without improving the system”

ポイント12問の誤答36個は、この6つで全部説明がつく。最も多いのは① 事実で消える（8個）で、知識だけで消える。残りは「対処の大きさ」と「原因の位置」を見れば絞れる。
