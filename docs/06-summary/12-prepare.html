6-12　読むだけで足りるか ─ 公式が勧める準備

公式 Exam Guide は「practical judgment（実際に手を動かして得る判断）を問う」と書いていて、そのための準備を 7つ挙げ、演習を4本用意しています。ここはその一覧です。

ゴール読んだあと、何を作って確かめればよいか分かる。

公式が勧める準備（7つ）中身対応する項
Agent SDK でエージェントを1つ作る ツール呼び出し・エラー処理・セッション管理まで通したループ。子を起こして文脈を渡すところまでやる 1-3 1-4 1-5 1-6 1-13 1-19
実際のプロジェクトで Claude Code を設定する CLAUDE.md の階層、.claude/rules/ のパス固有ルール、frontmatter つきのスキル（context: fork・allowed-tools）、MCP サーバを1つ以上つなぐ 3-2 3-3 3-7 3-5 2-6
MCP ツールを設計して、試す 似た道具を書き分ける説明文、種別と再試行可否つきのエラー応答。曖昧な依頼を投げて、狙った道具が選ばれるか確かめる 2-2 2-3 2-4
構造化抽出の仕組みを1本通す tool_use ＋ JSON スキーマ、検証と再試行の輪、任意（null 可）の項目、Message Batches API でのバッチ処理 4-10 4-11 4-13
プロンプトの手を練習する 曖昧な場面の few-shot、誤検知を減らす明示的な基準、大きなレビューを多段に割る形 4-7 4-8 4-14
文脈管理の型を身につける 長い返り値から事実を抜く、長丁場の作業メモ、窓を保つための子への委任 5-2 5-3 5-6
人に渡す判断を見直す 規約の穴・利用者の要求・進まないこと ⇄ 自分で解決。確信度で振り分ける人のレビュー導線を設計する 5-7 5-9

ポイント読んで分かることと、作って分かることは別。公式が挙げている7つは、どれもこの教材の節に対応しているので、読んだあとに同じ順で手を動かせる。

演習 ①　人に渡す判断つきの、複数ツール・エージェントを作る ねらい　ループにツールを組み込み、失敗を構造で返し、人へ渡す形まで通す　（Domain 1・Domain 2・Domain 5）
  1. 説明文を書き分けた MCP ツールを3〜4本定義する。うち2本は似た機能にして、取り違えないか試す
  2. stop_reason を見てループを回す。tool_use と end_turn の両方を正しく扱う
  3. errorCategory（一時的／検証／権限）と isRetryable、読める説明を返す。種別ごとに扱いが変わるか確かめる
  4. 業務規則（一定額を超える返金など）を止めるフックを入れ、人へ回す道に差し替える
  5. 用件が複数ある依頼を投げ、分けて調べ、1つにまとめて返すか確かめる
演習 ②　チーム開発向けに Claude Code を設定する ねらい　CLAUDE.md の階層・コマンド・パス固有ルール・MCP を、複数人の前提で組む　（Domain 3・Domain 2）
  1. プロジェクトの CLAUDE.md に共通の規約を書き、全員に効くことを確かめる
  2. .claude/rules/ に paths つきのルールを作り、該当ファイルを開いたときだけ載ることを確かめる
  3. .claude/skills/ に context: fork と allowed-tools つきのスキルを作り、本体の会話が汚れないことを確かめる
  4. .mcp.json に環境変数の展開つきでサーバを設定し、個人用を ~/.claude.json に足して、両方見えることを確かめる
  5. 難しさの違う3つの作業で plan mode と直接実行を比べ、どこから plan mode が効くかを見る
演習 ③　構造化抽出の仕組みを作る ねらい　スキーマ設計・検証と再試行・バッチ・人のレビュー導線を、ひと続きで組む　（Domain 4・Domain 5）
  1. 必須と任意、enum（「その他」＋詳細）、null 可の項目を持つスキーマを定義し、無い項目を作らずに null で返すか確かめる
  2. 検証に落ちたら、元の文書・失敗した出力・具体的な指摘を添えて投げ直す。直る失敗と直らない失敗を数える
  3. 書式の違う文書の few-shot を足して、扱いが安定するか見る
  4. 100件をバッチで投げ、custom_id で失敗を拾い、直して投げ直す。締め切りから間隔を逆算する
  5. 項目ごとの確信度を出させ、低いものを人へ回す。書類種別・項目ごとに精度を見る
演習 ④　複数エージェントの調査を組んで、壊れ方を見る ねらい　委任・文脈の受け渡し・失敗の伝播・出典を保った統合を、実際に壊しながら確かめる　（Domain 1・Domain 2・Domain 5）
  1. 親から子を2体以上起こす。親に子を起こす道具を渡し、子には結果を指示の中で直接渡す
  2. 1つの応答に複数の呼び出しを入れて並列に起こし、順に起こした場合と待ち時間を比べる
  3. 子の返す形を「主張・根拠の引用・出典・日付」に分け、統合の子が出典を保つか確かめる
  4. 子を1体わざとタイムアウトさせ、親に失敗の種類・試したこと・途中まで得たものが届くか、そのまま先へ進めるか確かめる
  5. 食い違う数字を持つ資料を2つ与え、片方を選ばずに両方を出典つきで残すか確かめる

※ この一覧は公式 Exam Guide の「7. How to Prepare」と「8. Preparation Exercises」を写したものです（原文は参考資料から）。
※ 全部を作る必要はありません。設問を解いて手が止まったところから選ぶのが早道です ── どこで止まったかは、直前の理解度チェックが教えてくれます。
